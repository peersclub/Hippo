Ask Hippo live · BTC

A two-stage flow: a fast model interprets and rewrites your query first (you see a persistent "UNDERSTOOD" card), then the research engine answers. Numbers are always retrieved from the live feed — the model only writes prose, so it can't fabricate a price.

Area 04 · Spot orders

Spot — market, limit, cancel live · BTC

Talk to Hippo (parasite path, HMAC-signed) or use the host's own ticket (human path) — both hit the same wallet and book, so orders show in the native blotter and Hippo's positions card alike. Seed wallet: 100,000 USDT · 2 BTC · 20 ETH.

TestTry (any live symbol — BTC/ETH/SOL)Expected result
Market buybuy 0.01 BTC → confirmticket → rests ACTIVE ~2.5–3s (working window) → FILLED; BTC +0.01, USDT −notional −0.1% taker fee.
Limit (rests)buy limit well below market (e.g. @30000)stays ACTIVE indefinitely; fills at the limit rate only when price crosses.
Cancelcancel a resting orderdrops from open orders; reserved funds released.
Insufficient balancebuy 100 BTC marketrejected up front (400): "insufficient USDT: need …, have 100000" — no order created.
Partial fillvenue drawer → enable Partial fills, then a market orderfills in two steps: PARTIAL (half) → SETTLED; the lifecycle card shows both.

By design: a market order isn't instant — it rests ~2.5–3s so the reconciler (polls every 2s) can observe the fill. The balance figure includes reserved funds, so it won't visibly drop when a resting order locks margin.

Area 07 · Resilience & edge cases

It degrades honestly, never hangs fault injection

InjectExpected result
AI service downpkill -f uvicorn, ask a research question → never-500: a truthful market-data-only brief + an amber "HIGH MARKET LOAD" banner. Orders + prices keep working.
Gateway restartSSE drops; the SDK re-mints a fresh session (backoff 1s→30s) instead of hanging. (Durable cold-resume needs Redis.)
Order stuck workingafter TICKET_EVENT_TIMEOUT_MS (10 min) a backstop closes the card with a terminal "expired" frame — it can't hang forever.
Server dies mid-stream20s after the last delta a client watchdog finalizes the card instead of blinking forever.
Offline actionschip tap / feedback / settings buffer (FIFO, cap 20) with an "{n} QUEUED" row, drain in order on reconnect. Trading actions are never queued — they fail loud.

Known limitations

Called out honestly

⚠ Answer language is English-only through the SDK

The intelligence service can write Hindi/Hinglish, but the gateway forwards language only to intent classification, not the answer path — so briefs/declines come back in English regardless of selected language. Arabic is chrome + RTL layout only. Not wired end-to-end yet.

⚠ Prod-only behaviours + Redis

The 401 "blocked" quiet-disable and 429 "busy this month" notice only fire against the production gateway (HIPPO_DEV=0). Redis is optional (in-memory sessions/cache today); add REDIS_URL for multi-instance or restart-durable deploys.
